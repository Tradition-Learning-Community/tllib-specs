## Global catalog

`handoff/catalog.json` is a deterministic projection generated by `tools/handoff/generate_catalog.py`. It contains the 16 domains in authoritative order, all 166 feature descriptors, exact package/scientific/execution statuses, examples presence, resolved shared dependencies, package and descriptor SHA-256 fingerprints, tool versions, and explicit null deprecation/substitution fields.

The exact manifest-derived distributions are:

- package: 165 `finalized`, 1 historical foundation `pilot`;
- scientific: 108 `preserved_unresolved`, 29 `partially_defined`, 29 `external_provider_required`;
- execution: 143 `structural_only`, 23 `conditionally_executable`;
- examples: 1 present, 165 absent.

No timestamp or other volatile generation field is permitted. CI reconstructs the catalog from the committed handoff artifacts and requires exact equality.

## Validation authority

`tools/handoff/validate_handoff.py` is the sole normative validation CLI. The former compatibility CLI was removed only after its strict historical-reading controls were integrated.

The canonical validator accepts established inventory aliases in read mode, checks every alias present, preserves ordered list and mapping populations, and rejects missing, conflicting, non-integer, inaccurate, or reordered evidence. It also validates schemas, exact package files, domain ownership, dependency unions, traceability, test and error identity, strategy order, global catalog equality, and absence of normative implementation-language code.

The workflow invokes this one CLI, its A–K logical self-tests, deterministic catalog checking, and complete export validation.

Eighteen candidates are recorded as compositions of existing shared contracts, sixteen remain future candidates, and eight are rejected as semantically distinct. The complete per-candidate decisions are in `shared-contract-decisions.json`.

## Standalone exports

`tools/handoff/export_bundle.py` resolves each catalog feature into exactly:

```text
feature/
shared/
bundle-lock.json
```

The lock records feature and model versions, transitive shared contracts, source and bundle paths, ordered SHA-256 file records, per-shared-package hashes, and an aggregate bundle hash. It contains no timestamp. Scientific sources, registry artifacts, and intermediate IRs are never copied.

The permanent workflow selects all 166 catalog features and generates each bundle twice in independent temporary directories. Lock objects and every relative-path hash map must be byte-for-byte identical. Bundle archives are not committed.

## Quality and simulations

The validator rejects packages with undeclared or missing files, empty acceptance plans, incomplete traceability categories, unresolved paths, duplicate tests or errors, invalid strategy edges, incorrect dependency sets, insufficiently specific README files, or normative C++, Rust, Ruby, or Python code.

Eight standalone simulations cover the foundation descriptor, symbolic Dynamics structure, external provider boundary, normative source order, non-executable scientific errors, no-examples packaging, multiple historical IRs, and unresolved Relations endpoints. Every simulation is implementable from the exported bundle while preserving opaque or unresolved science.
